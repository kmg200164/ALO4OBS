## 확인한 현재 구조와 적용 범위

10/7 공개 README와 다운로드 ZIP(0.8.0)을 읽기 전용으로 확인했다. 원격 main의 다음 변경은 Windows 세션이 pull 후 다시 대조한다.

- UI 강조색은 `template/header.js`의 `#accent-color` 입력, `overlay-ui-accent` 로컬 저장값, CSS `--accent` 경로다. 확인한 ZIP 내부 경로는 `files/internal/header.js`이며 UI 초기 색은 `#d4ff00`이다.
- UI 테마는 `overlay-ui-theme`와 `body[data-theme]`로 보관한다. header.css에 `#1E1E1E` / `#E8E8E8` 배경 하드코딩이 있어 함께 점검한다.
- 방송 콘텐츠의 `config.accent`, `config.panel`, `config.text`, `backgroundColor`와 UI 강조색은 별개다. **이번 변경은 UI 테마 프리셋**이며, UI 테마 전환 때문에 사용자의 방송 배경·미디어·출력 스타일이 바뀌면 안 된다.
- 사용자가 제공한 AML 레거시 Figma 스크린샷에서 한정된 색상 모드와 라이트·다크 값의 구조를 참고한다. AML 변수·코드·팀 시안을 가져오거나 해당 Figma 파일을 수정하지 않는다.
- 색 선택 방식은 사용자 예시에 따른 프리셋 방식으로 진행한다. 아래 HEX는 계산 확인한 구현 시작 후보이고, 사용자가 최종 색상 HEX를 확정한 것은 아니다. 실제 UI에서 같은 계열의 밝기·채도를 조정하고 변경값과 근거를 보고한다.

[2-2] 알로에 기본값 + 라이트/다크 대응 UI 프리셋
- 헤더의 자유 색상 입력(type=color)을 없애고 같은 위치에서 한정된 프리셋을 고르게 한다. 초기 프리셋은 Aloe(알로에, 기본), Blue, Pink, Orange. 색상명과 작은 스와치, 선택 체크를 함께 표시하고 색만으로 선택 상태를 구분하지 않는다. ko/en/ja 라벨·접근성 이름·키보드 선택을 지원한다. 기존 헤더 구성·가이드/설정 전환은 유지한다.
- Theme(light/dark)와 Accent preset(Aloe/Blue/Pink/Orange)은 독립 축이다. 테마를 바꿔도 선택한 프리셋 ID는 유지하고 해당 테마용 토큰 묶음으로 전환한다. Light=어두운 강조색, Dark=밝은 강조색을 기본으로 하며 같은 HEX를 양쪽에서 쓰지 않는다.
- 색 정의는 한곳에 모으고 primitive palette → semantic 역할 토큰 → 컴포넌트 참조로 연결한다. 프로젝트의 기존 CSS 변수 이름은 조사 후 최소 변경으로 유지하거나 alias한다. 컴포넌트 안에서 프리셋별 HEX 분기·색 하드코딩을 늘리지 않는다.
- 필수 역할: page/background, surface/card, surface/field, content/primary, content/secondary, border/control, accent/default, accent/hover, accent/pressed, content/on_accent, surface/accent_subtle, content/on_accent_subtle, focus/ring, selection/indicator. warning/error/success/info는 독립 상태 토큰으로 두고 선택한 브랜드 프리셋에 따라 의미가 바뀌지 않게 한다.
- 배경과 카드에는 해당 프리셋 색을 아주 옅게 넣어 어울리게 한다. 채도 높은 배경으로 만들지 않는다. 실제 미디어·사용자가 설정한 방송 배경은 손대지 않는다. 그림자·투명 표면을 쓰면 최종 합성 배경에서 대비를 계산한다.
- 시작 후보(순서: accent / page / surface / on_accent):
  Aloe light: #356447 / #F4F7F3 / #FFFFFF / #FFFFFF
  Aloe dark:  #91C9A0 / #131B16 / #1C2920 / #13251A
  Blue light: #245D86 / #F3F6F9 / #FFFFFF / #FFFFFF
  Blue dark:  #8ABDE0 / #141B22 / #1D2934 / #102434
  Pink light: #8C4167 / #F9F4F6 / #FFFFFF / #FFFFFF
  Pink dark:  #DDA3C0 / #21181D / #30232B / #301625
  Orange light: #8A4B22 / #F9F5F1 / #FFFFFF / #FFFFFF
  Orange dark:  #E7B184 / #211A14 / #30261D / #302010
  위 후보의 accent 대 page/surface, on_accent 대 accent 대비는 sRGB 계산에서 모두 4.5:1 이상이다. 이것만으로 전체 UI 검수가 끝난 것은 아니다. secondary text, border, hover/pressed/focus 등 나머지 역할도 값을 정의하고 실제 대상 배경별로 별도 확인한다.
- 일반 글자 4.5:1 이상, UI 조작·상태를 식별하는 필수 아이콘/윤곽 3:1 이상을 기준으로 검수한다. 색상명·체크·라벨을 보조 단서로 유지한다. 색감만으로 눈의 편안함이나 접근성을 보장한다고 주장하지 않는다.
- 헤더 제목·버전·아이콘·후원/버그 링크, 가이드, 설정 카드/입력/체크/슬라이더, 경고·저장/적용/초기화 버튼, 드롭다운과 모달까지 실제 semantic 역할을 대조한다. filled accent 버튼에는 content/on_accent, 일반 링크에는 accent/default를 써서 배경에 맞는 글자색을 선택한다.
- 기본값·복원: 새 사용자와 유효하지 않은 프리셋 ID는 Aloe. 신규 저장에는 프리셋 ID를 사용한다. 기존 overlay-ui-accent 임의 HEX는 삭제하지 않고, 최초 마이그레이션에서 새 프리셋 미선택 시 Aloe로 전환한다. 옛 inline --accent가 새 semantic 값을 덮어쓰지 않게 한다. overlay-ui-theme와 다른 저장 데이터는 유지한다. 마이그레이션은 한 번만 적용하고 이후 선택은 reload·가이드/설정 전환에서도 유지한다.
- UI 테마는 현재처럼 브라우저의 UI 설정 범위로 유지한다. 프리셋 ID 때문에 방송 config 스키마나 OBS-settings.zip 출력 형식을 무조건 바꾸지 않는다. 현재 UI 설정의 export/import 경로가 별도로 있으면 그 경로만 호환성을 점검한다. 방송 설정 ZIP을 불러와도 사용자의 패널·미디어·방송 배경은 유지돼야 한다.
- 최소 회귀 확인: 4프리셋 × 2테마, 최초 실행/옛 HEX 저장/유효 프리셋/미지원 ID, reload·테마 왕복·가이드 왕복. 각 조합의 hover/pressed/focus/selected와 경고를 확인한다. ZIP 생성→같은 방송 설정을 OBS에 적용해 출력이 UI 테마 변경으로 달라지지 않는지 확인한다.

## 업데이트 뒤 Mac 테스트·촬영

이 절은 **Windows 구현 세션의 보고 뒤 다음 작업**이다. 오늘 0.8.0으로 홍보 영상을 촬영하지 않는다. Windows 세션은 위 금지·보고 경계에서 멈춘다.

1. Windows에서 0.8.1 구현·QA·ZIP 생성 → 사용자 확인. ZIP 버전·해시를 기록한다.
2. 같은 ZIP을 Mac으로 가져와 압축을 풀고 `settings.html`을 연다. 개인 설정이 없는 별도 테스트 데이터와 본인 제작 더미 미디어를 사용한다. Mac에서도 `file://` 열기, 테마/프리셋, 패널 개수·간격·Side 전환, ZIP 내보내기와 재열기를 확인한다. HTTP 미리보기로 file:// 검증을 대신하지 않는다.
3. Mac OBS에서 도구→스크립트→`OBS-script.lua`→설정 적용까지 확인한다. Windows와 브라우저 viewport/배율/앱 버전을 기록해 배치를 비교한다. 같은 UI 코드라는 이유로 OS 저장·압축·OBS 동작이 같다고 추정하지 않는다. 문제가 남으면 macOS 지원 완료를 주장하지 않고 Windows 검증과 구분해 보고한다.
4. 실제 0.8.1 화면으로 “설정 과정 → 자동 배치 변화 → OBS 적용 결과”를 녹화한다. 영상 미학은 Mac 촬영에서 다듬되 Windows 지원 검수를 대체하지 않는다. 패키지 배포와 실제 게시는 기존 사용자 승인 조건을 따른다.
5. [10-12 마케팅 시안](../이력서%20자기소개서%20개인%20컨설팅/10-12%20마케팅%20시안/10-12%20마케팅%20시안.md)의 촬영 구성·표기·공개 조건으로 검토본을 만든다. 기본 채널은 Instagram Reels와 X, 같은 세로 영상의 YouTube Shorts 활용은 후보로 둔다. 추가 계정·운영 루틴은 만들지 않는다.

실제 화면을 쓰되 화면 안에 타인의 얼굴·닉네임·게임/방송 IP·토큰·개인 widget URL을 넣지 않는다. OBS 로고를 홍보 자산으로 추출하지 않는다. 앱 화면은 기능 시연 맥락으로 사용한다. 음악은 무음 기본이며 추가할 때만 사용 조건·출처를 확인한다. 캡션은 AI 활용·비제휴·Release 상태를 정확히 표시한다.
