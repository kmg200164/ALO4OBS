# ALO4OBS 0.8.0 작업 지시문과 논의 기록

이 문서는 Grok Bot이 없어도 vault만 보고 0.8.0 작업을 이어 갈 수 있게 남긴 정본이다. 2026-10-06 하루 동안 명기, Fredy(프론트엔드), Jecky(프로젝트 관리), Maki(마케팅)가 나눈 결정을 모두 합쳤다. 지시문은 Fredy가 쓴 [0]~[5]와 추가분 [3-1]~[3-9]를 하나로 묶은 최종본이다. 앞뒤가 서로 어긋나던 부분(zip 이름, CHANGELOG 버전)은 나중 결정에 맞춰 고쳤다.

- **쓰는 법:** Windows에서 `W:\Project\OBS-streaming-template` 폴더를 열고, Claude Code(경고 문제가 있으면 Codex)에 아래 "지시문 전문" 코드 블록을 통째로 붙여 넣는다.
- **끝난 뒤:** 보고 결과를 vault 허브 [[alo4obs|ALO4OBS]]의 "현재 상태"에 반영하고, 이 문서의 "남은 일"을 지운다.
- **병렬 실행:** Opus high로 돌릴 때는 subagent-orchestration의 블록을 지시문 맨 위에 먼저 붙인다(하위 에이전트로 나누고 작업마다 모델·노력량을 맞춤).
- **착수일:** 10/7부터(10/6 저녁은 박재범 멘토링).

[3-2] 다운로드 zip 파일명에 버전 붙이기
- pack.js(또는 build.py)가 만드는 사용자용 zip 이름을 "ALO4OBS-v{버전}.zip" 형식으로 바꾼다. 첫 정식 버전은 ALO4OBS-v0.8.0.zip이다.
- 버전 값은 손으로 적지 말고 template/version.js 한 곳에서 읽어 온다.
- version.js를 0.8.0으로 올리는 건 정식 Release 때 한다. 지금은 0.7.1 그대로 두고, downloads/의 0.7.1 파일과 README 다운로드 링크도 건드리지 않는다.
- tests/pack.test.cjs에 파일명에 버전이 붙는지 확인하는 테스트를 추가한다.

[3-3] OBS 장면·소스 접두사 변경: "OST ·" → "ALO ·"
- OBS-script.lua(약 33곳)와 테스트(약 9곳)의 "OST ·" 접두사를 "ALO ·"로 바꾼다. 띄어쓰기와 가운뎃점 형식은 기존과 똑같이 맞춘다. 먼저 전체 검색 목록을 보여 주고 바꾼다.
- 예전 "OST ·" 장면을 자동으로 바꾸거나 옮기는 코드는 만들지 않는다.
- 테스트와 롤백 코드가 새 접두사로만 동작하는지 확인하고, 예전 접두사가 코드에 남아 있지 않은지 다시 검색한다.
- README에 업데이트 방법을 짧게 적는다: (1) OBS에서 예전 "OST ·" 장면과 소스를 통째로 지운다 (2) 새 ZIP으로 다시 설정한다 (3) 스크립트를 다시 올린다. 롤백은 같은 버전 안에서만 된다는 점도 적는다.

[3-4] 패널 이름을 역할 이름으로 변경
- "패널 1~7"을 다음 이름으로 바꾼다: 1 Main, 2 Sub 1, 3 Sub 2, 4 Sub 3, 5 Side 1, 6 Side 2, 7 Side 3.
- Sub·Side 번호는 화면에 실제로 놓이는 순서(왼쪽→오른쪽, 위→아래)와 맞춘다. 지금 번호와 실제 배치가 다르면 먼저 표로 보여 준다.
- 반영할 곳: 설정 화면, 미리보기 번호 표시, i18n, 오류 문구, OBS 장면·소스 이름(예: "ALO · Main", "ALO · Sub 1"), README, 테스트.
- 내보낸 설정 JSON 키는 바꾸지 않는다(공통 규칙). 구조상 꼭 바꿔야 한다면 이유를 보고하고, 예전 설정 복원이 깨진다는 사실을 README 업데이트 안내에 적는다.
- OBS 장면·소스 이름이 바뀌는 건 [3-3]의 업데이트 방법으로 함께 안내한다.

[3-5] Side 위치 조정 옵션 제거
- 너비·높이를 직접 정할 수 있으니 Side 위치를 바꾸는 옵션(UI, 상태값, 저장·내보내기 항목)을 뺀다.
- Side에는 켜기·끄기만 남긴다. 위아래 바꾸기는 Main과 Sub에만 남긴다.
- 예전 설정에 Side 위치 값이 있으면 오류 없이 무시하고 기본 위치로 복원한다. 이 경우를 확인하는 테스트를 추가한다.

[3-6] 빈 공간·넘침 경고
- Sub 세 개가 모두 Manual이고 너비 합(패널 간격 포함, [3-9])이 위쪽 왼쪽 프레임 너비보다 작아 빈 공간이 생기면, 패널을 자동으로 바꾸지 말고 경고만 띄운다.
  문구(한): "빈 공간이 생겼어요. Sub 패널 하나의 너비를 자동으로 바꾸면 채워져요." 영·일 문구도 같은 뜻으로 넣는다.
- 너비 합이 프레임보다 커서 넘칠 수 있으면 같은 자리에 넘침 경고를 띄운다.
- 경고는 Sub 너비 설정 가까이에 두고, 기존 디자인 토큰과 컴포넌트를 쓴다.
- 경고가 있어도 저장과 OBS 적용은 막지 않는다.
- 테스트: 딱 맞음 → 경고 없음 / 모자람 → 빈 공간 경고 / 넘침 → 넘침 경고 / Auto가 하나라도 있음 → 경고 없음 / 경고가 있어도 저장과 적용이 됨.

[3-7] README와 Release에 최신 패치노트 보여 주기
- 일반 사용자는 CHANGELOG.md가 있는 줄도 모르니, README 다운로드 링크 근처에 "이번 버전에서 바뀐 점"을 넣는다. 최신 버전 하나만, 3~6줄, 사용자 눈높이 문장으로 쓴다.
- 전체 기록은 CHANGELOG 링크로 넘긴다.
- 0.8.0 패치노트는 [3-3]의 업데이트 방법(예전 장면 삭제 → 재설정 → 스크립트 재업로드) 안내로 연결한다.
- 같은 패치노트를 정식 Release 본문용 마크다운으로도 따로 만들어 보고에 넣는다.

[3-8] 헤더 다시 짜기
1) 가이드 버튼 아이콘을 Lucide `book-open`(펼친 책)으로 바꾼다. 크기·선 굵기·속성은 [2]와 같은 규칙.
2) 헤더 왼쪽 묶음: 서비스 이름 "ALO4OBS" 오른쪽에 아래 버튼을 이 순서로 붙여 이름과 한 묶음으로 왼쪽에 둔다.
- 버전: template/version.js 값을 읽어 "v0.7.1"처럼 표시한다(Release 때 0.8.0으로 자동 반영). 손으로 적지 않는다.
- GitHub: 원래 오른쪽에 있던 GitHub 버튼을 이 묶음으로 옮긴다. 주소는 config.public.js의 저장소 주소.
- 버그 신고: 저장소 issues/new로 연결한다. 아이콘은 Lucide에서 고른다.
- 후원하기: 아이콘은 Lucide `heart`. template/config.public.js에 후원 주소 https://buymeacoffee.com/kmg200164 를 넣고 버튼을 켜 둔다. 다른 후원 플랫폼은 없다. 주소가 비어 있으면 버튼을 숨기는 처리는 안전장치로 남긴다.
- README의 Buy Me a Coffee 링크(지금 7줄 문장 링크, 12줄 버튼 이미지 링크)와 config 주소가 똑같은지 비교해 보고한다.
3) 나머지 버튼(언어, 다크/라이트 등)은 지금처럼 오른쪽 정렬을 유지한다.
4) 설정 | 가이드 두 칸 탭: 헤더 오른쪽의 설정 버튼과 가이드 버튼을 한 묶음의 두 칸짜리 탭(segmented control)으로 바꾼다. 지금 보고 있는 페이지 칸에 aria-current="page"를 달고 눈에 띄게 칠한다. 라벨은 한·영·일. 좁은 화면에서 탭이 다른 헤더 요소와 겹치지 않는지 확인하고 보고에 캡처를 넣는다.
5) 새 버튼 모두 aria-label·title을 단다. 외부 링크는 새 탭으로 열고 rel="noopener"를 붙인다.

[3-9] 간격 5단계 선택 (패널 간격과 바깥 여백을 하나로)
- 지금 32px로 고정된 "패널 사이 간격"과 "화면 가장자리 바깥 여백"을 "간격" 설정 하나로 묶는다. 고른 값이 패널 간격과 바깥 여백에 똑같이 들어간다. 대부분의 방송인은 디자이너가 아니라서 설정을 하나로 줄인다.
- 5단계: 매우 좁음 8 / 좁음 16 / 보통 24 / 넓음 32 / 매우 넓음 48(px). 기본값 넓음(32)이라 기존 화면은 그대로다.
- 여백 0(패널이 화면 끝에 붙는 단계)은 넣지 않는다. 패널 테두리가 없던 초기 시안 방식이라 지금 디자인과 맞지 않는다.
- UI는 다른 5단계 옵션과 같은 슬라이더 컴포넌트 하나로 만든다. 라벨은 한·영·일.
- 값은 디자인 토큰(CSS 변수) 하나로 두고, 패널 사이 gap과 바깥 여백이 모두 이 변수를 쓴다. 배치 계산(Sub 자동 너비, [3-6] 빈 공간·넘침 경고 포함)도 이 값을 따른다. 32를 직접 쓴 곳을 먼저 찾아 목록을 보여 준다.
- 저장·내보내기에는 값 하나로 넣는다. 예전 설정 파일에 값이 없으면 넓음(32)으로 복원한다.

[4] 첨부 파일 유지 검증
- 문제: HTML을 껐다 켤 때마다 첨부해 둔 파일이 초기화됐다. 앞선 작업에서 고쳤다면 실제로 고쳐졌는지 확인한다.

[5] 구조 원칙 점검 (보고만, 수정은 승인 후)
