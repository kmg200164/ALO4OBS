ALO4OBS
Auto Layout Overlay for OBS — 0.10.2

ALO4OBS-v0.10.2.zip is this distribution archive. Settings-Bento.zip / Settings-Overlap.zip is your personal saved application package.

1. Use OBS Studio 30.1 or newer with Browser Source and Tools > Scripts. The script needs obs_sceneitem_get_info2 / obs_sceneitem_set_info2 (30.1 APIs); isolated Windows OBS 32.2.2 migration checks passed in the scope below. macOS is unverified for this version.
2. Use a 1920 x 1080 base canvas (Settings > Video). Choose a separate profile if your production profile uses another size; do not overwrite it arbitrarily.
3. Extract the entire distribution. Open root settings.html (it opens files/settings.html), never a page inside the ZIP.
4. First choose Bento (4 columns) or Overlap (5 columns). Switch layout returns to this chooser; each layout retains its layout and panel settings. Main and global appearance are shared. Bento uses Main, Sub and Side; Overlap uses Main and 15 independent panels named Panel 1-1 through Panel 5-3. Select a panel and Content type: None, OBS source, Web URL or Image/video.
5. For OBS source, create and verify the original capture or camera in OBS first. Scenes/groups are not panel source choices. For web widgets use the OBS display URL; for media upload a file or enter its direct URL.
6. Set layout, sizes, spacing and styles. In Bento, Sub runs left to right and Side top to bottom; their counts and row/column positions can change. In Overlap, Main fills 1920 x 1080. Fresh Overlap enables all five columns and all 15 panels, with the 5-column width basis (355.2 px), Manual heights 328 px and Manual Y positions 24/376/728 px at gap 24; an Enabled switch controls visibility and a count slider selects 1-3 panels. Columns 1, 3 and 5 offer a Wider width switch: 5-column basis when off, 3-column basis when on. Wide neighbors temporarily suppress columns 2 and 4 without clearing saved settings. Disabled columns retain their horizontal slots and all settings; disabling a column does not move the other columns. Names identify each panel's fixed column and default row. Select visible panels in the preview and choose Auto or Manual pixel height. Red/yellow warnings do not block use. UI theme colors do not change broadcast colors.
Overlap panels keep their named column. Height Auto / Manual controls are toggle switches in both layout types; Bento also has width Auto / Manual switches. Select Overlap Main using the clickable tag outside the preview. In Panel position, Auto uses a vertical Top / Center / Bottom slider to align the whole column stack while keeping panel gaps; Manual stores the requested Y coordinate. Feasible requests remain pinned when column alignment changes. Drag a panel vertically in the preview to switch to Manual, or use its Y number/slider. A feasible Manual Y stays fixed; when sizes, counts or gaps make it unsafe, rendering clamps it to the ordered neighbours while retaining the saved request. Auxiliary panels never overlap; only full-screen Main sits underneath them. The safety guide stays fixed and uses color only, without panel numbers. Hidden panels retain positions, and both layout snapshots carry them through save/reopen and ZIP export. Minimum auxiliary height is 128 px. Y is bounded by the outer gap and the neighbouring panels, preserving their order and spacing. Applied height and Y are fitted to available space while preserving the 128 px minimum, panel order and gaps; saved requested height and Y survive unrelated edits.
7. The ZIP is fully assembled before a standard browser download starts. The browser download settings determine its destination; the editor no longer creates a file through the native save picker. Click Save as ZIP (Korean: ZIP 파일로 저장). Save your personal Settings-Bento.zip / Settings-Overlap.zip.
8. Extract the entire personal ZIP to a permanent folder. Keep OBS-script.lua with configuration, masks, media/assets and runtime files. Moving only Lua breaks relative paths.
9. In OBS, Tools > Scripts > +, select that folder's OBS-script.lua. Enable English UI (reload after changing) and reload if needed.
10. Reselect a distinct original OBS source for each panel you want to show; a blank selector intentionally leaves it empty. Click Apply saved settings / Auto layout (Korean: 저장한 설정 / 자동 배치 적용).
11. Open the ALO4OBS · BENTO or ALO4OBS · OVERLAP scene and verify real capture, camera, widgets and media. The browser preview cannot show your real OBS content.

Overlap uses a full-canvas Main and 15 independent panels, Panel 1-1 through Panel 5-3, on a 5 x 3 grid. Its red/yellow/green safety guide is editor-only and game-specific. All 15 cells are shown; red/yellow cells allow placement and show warnings only. Each panel has independent content, visibility, regional style and shadow. Auxiliary panels stack within their named columns. Global radius: 8/16/24/32/48 px; three-step smoothing slider: 0/60/100%. Fresh macOS settings start at60%, other platforms at0%; stored values win. Global shadows have an off switch and five strengths; panels inherit them unless the individual-style override is enabled. Local shadow controls appear with fill/stroke inside that override. Five Enabled switches and count sliders (1-3) preserve hidden panels' content, styles, heights, positions and widths. Overlap widths use the fixed 5-column or 3-column basis. Legacy pixel widths remain stored but no longer determine geometry. Safety cells retain the original 5 x 3 positions. Fresh settings enable three panels per column; enabled panels run from row 1 through the saved count. Auto divides remaining height; Manual sets pixels. Select panels directly in the preview. Legacy development positions are corrected to their named column; the original browser draft is backed up once locally before migration. If backup storage is blocked or full, the original durable draft is preserved and current edits remain session-only; save a ZIP to retain them. Overlap Main has no rounding, stroke or shadow.

UPDATING
Export your OBS scene collection, back up the entire old application folder, and record script source selections. Keep old packages intact; use a new distribution folder.
The editor reads config.js, not JSON imports. After old-script Apply, copy its generated config.js (from layouts/bento/ or layouts/overlap/ in type-specific packages) into the new distribution files/ folder, plus only personal media from the matching runtime folder referenced by assets/... paths, preserving those paths. Keep the new config.public.js, internal scripts and fonts. If config.js is missing, Apply once in the old version to generate it, or manually reconfigure while keeping the old environment. Do not rename JSON to simulate an import. Browser drafts at a new path are not guaranteed.
Check the new settings page, export a new Settings-Bento.zip / Settings-Overlap.zip and extract to a new permanent folder. Remove only the old Lua registration after recording selections. Add the new Lua path, reselect original sources before Apply, and verify in OBS. A new registration does not import old selector mappings from JSON. Apply reuses the selected ALO4OBS · BENTO or ALO4OBS · OVERLAP scene and items whose names start with that scene name and intentionally restores template layout. Original source settings/filters are intended to remain, while template scene-item transforms are reset. Other scenes are not edited directly, but reused type-specific sources/groups share content updates. Disabled groups retain originals as hidden root items. Reserved-name collisions abort Apply; inspect conflicts instead of blindly deleting sources. The isolated Windows OBS 32.2.2 migration/preservation checks below passed. Controlled internal failure recovery also passed in 0.10.0; device/plugin failures are outside that test scope.
For legacy OST, keep OBS Streaming Template, OST · groups, original sources and the complete old script folder. Stop/remove only the old script registration. Configure new panels with the same originals; Apply builds a separate ALO4OBS · BENTO or ALO4OBS · OVERLAP scene. Apply each type once to create both; existing single ALO4OBS scenes are retained. Verify before switching. No automatic OST migration or blanket source/group deletion.
For an ALO4OBS update rollback, import the pre-update scene-collection backup into a separate recovery collection without overwriting the current collection. Restore the matching old Lua script and entire old application folder, then verify original source mappings. The update reuses the selected type-specific ALO4OBS scene and changes generated browser-source local_file paths; selecting the same scene and registering old Lua alone does not restore the previous setup. Switching directly to the preserved old scene applies only to parallel legacy OST migration, where the OST scene remains separate. Full recovery is not guaranteed without the previous scene-collection and full application-folder backups. A live rollback snapshot works only with the same running script/version and is not an installation-update backup.
