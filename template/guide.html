설정과 OBS 연결

그림의 순서대로 시작하세요. 자세한 내용은 아래 제목을 눌러 확인합니다.

빠른 시작

필수 안내

1. OBS 준비

OBS Studio 30.1 이상에서 브라우저 소스와 도구 → 스크립트를 사용할 수 있어야 합니다.

설정 → 비디오의 기본 캔버스를 1920 × 1080으로 사용합니다. 기존 방송 프로필이 다른 크기라면 별도 프로필을 만들거나 선택하세요. 기존 방송 프로필을 임의로 바꾸지 마세요.

2. 배포 파일 열기

배포 파일 ALO4OBS-v0.9.1.zip을 전체 압축 해제하고 루트의 settings.html을 엽니다. 이 파일은 files/settings.html을 엽니다. ZIP 안에서 HTML을 실행하지 마세요.

3. 패널과 콘텐츠 선택

Main · Sub 1–3 · Side 1–3 중 설정할 패널을 선택합니다. 콘텐츠 종류에서 없음 · OBS 소스 · 웹 주소 · 이미지/영상을 고릅니다. 각 패널은 게임·채팅·캠 용도로 고정되어 있지 않습니다.

OBS 소스를 쓰려면 OBS에서 개별 캡처·카메라 소스를 먼저 만들고 영상이 나오는지 확인합니다. 장면과 그룹은 패널 소스로 선택할 수 없습니다. 웹 주소에는 제공자의 OBS 표시용 URL을, 이미지/영상에는 업로드 파일이나 직접 미디어 URL을 입력합니다. 동영상 시청 페이지 주소는 미디어 파일 주소가 아닙니다.

4. 배치와 스타일 설정

Main은 항상 켜져 있습니다. Sub와 Side 개수를 정하면 Sub는 왼쪽부터, Side는 위부터 표시됩니다. Main/Sub의 위아래 순서, Side 열 위치, 크기, 간격, 채우기, 테두리를 설정합니다. 미리보기로 배치를 확인하세요. 샘플은 실제 계정에 연결되지 않으며 실제 OBS 캡처 영상도 이 미리보기에 나오지 않습니다.

5. 개인 ZIP 저장·압축 해제

ZIP 파일로 저장을 누릅니다. 영어 버튼은 Save as ZIP입니다. 결과는 개인 적용 패키지 OBS-settings.zip입니다. 배포 파일 ALO4OBS-v0.9.1.zip과 구분하세요.

OBS-settings.zip을 새 영구 보관 폴더에 전체 압축 해제합니다. OBS-script.lua, JSON 설정, 마스크, assets/, 실행 파일을 함께 둡니다. 스크립트 위치를 기준으로 파일을 읽으므로 Lua만 옮기면 경로가 깨집니다. OBS 실행용 패키지에는 설정 편집기가 없습니다.

6. OBS에 연결하고 확인

OBS의 도구 → 스크립트 → +에서 방금 압축 해제한 개인 폴더의 OBS-script.lua를 선택합니다. 영어 스크립트 화면을 쓰려면 English UI (reload after changing)를 켜고 스크립트를 다시 불러옵니다.

표시할 OBS 소스 패널마다 스크립트의 같은 이름(Main · Sub · Side) 선택기에서 원본 소스를 선택합니다. 다른 패널에는 서로 다른 소스를 사용합니다. 선택기를 비워 두면 의도적으로 빈 패널을 둘 수 있습니다. 저장한 설정 / 자동 배치 적용을 누릅니다. 영어 버튼은 Apply saved settings / Auto layout입니다.

생성된 ALO4OBS 장면을 열고 캡처·카메라·웹 위젯·미디어가 실제로 나오는지 확인한 뒤 방송에 사용합니다. 설정 미리보기는 배치만 확인합니다. 브라우저 변경은 OBS에 자동 반영되지 않습니다. ZIP 재저장 → 전체 압축 해제 → 새 스크립트 경로 등록 또는 적용 폴더 갱신·스크립트 다시 불러오기 → 소스 선택 확인 → 자동 배치 적용이 필요합니다.

추가 팁

배치 컨트롤

화면의 일곱 칸은 Main, Sub 1~3, Side 1~3입니다. 용도는 게임·채팅·캠 등으로 고정되지 않습니다. 각 패널을 골라 없음 · OBS 소스 · 웹 주소 · 이미지/영상 중 하나를 정하고 스타일을 설정하세요. 미리보기의 패널 이름은 OBS 화면에 나오지 않습니다. 샘플은 실제 계정에 연결되지 않습니다.

기본 배치에서는 Main과 Sub 1~3이 왼쪽 프레임에, Side 1~3이 오른쪽 프레임에 위에서 아래로 놓입니다. Main은 항상 켜져 있습니다. Sub 개수와 Side 개수 슬라이더로 각각 1·2·3개를 고르세요. Sub는 왼쪽부터, Side는 위쪽부터 선택한 개수만큼 켜집니다. Main·Sub 위아래 바꾸기 스위치로 두 묶음의 위아래를 바꿉니다. Side 열 왼쪽에 놓기 스위치를 켜면 Side 열 전체가 왼쪽으로, Main·Sub 프레임이 오른쪽으로 이동합니다. Side 1~3의 위아래 순서는 유지됩니다.

전역 설정의 간격은 패널 사이 간격과 화면 가장자리 여백을 함께 정합니다. 매우 좁음 8px · 좁음 16px · 보통 24px · 넓음 32px(기본) · 매우 넓음 48px 중에서 고릅니다. Side 프레임은 왼쪽·오른쪽 위치와 무관하게 너비 440px을 유지하고 Main·Sub 프레임이 나머지를 씁니다.

Side 1~3의 높이와 Sub 1~3의 너비를 자동 또는 수동으로 선택할 수 있습니다. Main과 Side의 너비는 항상 자동입니다. 자동은 남은 공간을 채우고, 수동은 숫자 입력이나 슬라이더로 정한 픽셀 크기를 유지합니다. 활성 패널·간격·다른 수동 크기에 따라 입력 한도가 갱신됩니다. 켜진 Sub가 모두 수동인데 너비 합이 프레임과 맞지 않으면 크기를 바꾸지 않고 Sub 너비 설정 옆에 빈 공간 또는 넘침 경고를 보여 줍니다. 넘칠 때도 저장과 OBS 적용은 되며, 화면에서는 Sub 너비가 프레임에 맞게 줄어듭니다.

업로드한 이미지·영상은 같은 브라우저에서 같은 설정 페이지를 다시 열면 복원될 수 있습니다. 브라우저 데이터를 지우거나 파일을 옮기기 전에 설정 ZIP을 저장해 두세요.

Sub의 최소 너비는 Main이 16:9일 때의 기준 행 높이입니다(기본 206px). 그 외 최소값은 자동 크기의 50%, 최대값은 150%를 기준으로 하며 프레임과 다른 패널의 공간에 맞춰 제한합니다. Sub의 높이는 자동입니다. Main은 화면 비율에서 자동·16:9(기본)·21:9·32:9를 선택합니다. 자동은 Sub 묶음을 제외한 남는 높이를 채웁니다. 다른 축의 크기로 계산한 1:1·16:9 눈금 가까이 드래그하면 해당 비율에 맞춰집니다. 숫자 입력과 키보드는 정확한 값을 그대로 사용합니다.

OBS 버전과 검증 범위

스크립트는 30.1에서 추가된 obs_sceneitem_get_info2 / obs_sceneitem_set_info2를 사용합니다. 30.1은 최소 API 버전이며 아래 범위의 격리된 Windows OBS 32.2.2 이관 검수를 통과했습니다. 이번 후보의 macOS 검수는 아직 완료되지 않았습니다.

기존 ALO4OBS 업데이트

업데이트 전 OBS 장면 모음을 내보내고 기존 적용 폴더 전체를 백업한 뒤 스크립트의 패널별 소스 선택을 기록합니다. 기존 패키지는 그대로 보관하고 새 배포 파일은 별도 폴더에 풉니다.

설정 편집기는 JSON 가져오기가 아닌 config.js를 읽습니다. 기존 스크립트의 적용이 성공하면 개인 적용 폴더에 생성된 config.js를 새 배포 폴더의 files/로 복사합니다. 그 파일의 assets/... 경로가 가리키는 개인 미디어만 같은 상대 경로로 복사하세요. 새 config.public.js, 내부 스크립트, 글꼴은 교체하지 않습니다. config.js가 없으면 기존 버전에서 자동 배치를 한 번 적용해 생성하거나, 기존 환경을 보관하며 새 버전을 수동 설정하세요. JSON 이름 변경은 가져오기 방법이 아닙니다. 새 경로에서는 브라우저 임시 설정 복원을 보장할 수 없습니다.

새 루트의 settings.html에서 설정·미디어를 확인하고 새 OBS-settings.zip을 저장한 뒤 새 영구 폴더에 풉니다. 소스 선택 기록 후 기존 Lua 등록만 제거합니다(장면은 삭제되지 않음). 새 Lua 경로를 등록하고 적용 전에 원본 소스를 다시 선택하세요. 새 등록은 JSON에서 기존 선택기 값을 물려받지 않습니다.

구형 OST에서 전환

기존 OBS Streaming Template 장면, OST · 그룹, 원본 소스, 스크립트 폴더 전체를 보관합니다. 장면 모음을 내보내고 소스 선택을 기록한 뒤 기존 스크립트 등록만 중단·제거합니다. Lua 파일과 백업은 남깁니다. 새 버전에서 같은 원본 소스를 쓰도록 설정하고 새 스크립트를 등록한 뒤 소스를 다시 선택해 적용합니다.

새 ALO4OBS 장면은 별도로 만들어집니다. 확인 후 전환하고 기존 장면은 복구용으로 유지하세요. OST 장면을 자동 이관하지 않습니다. 소스나 그룹을 일괄 삭제하지 마세요.

복구와 검수 범위

자동 배치는 ALO4OBS 장면과 ALO · 항목을 재사용하고 원본 소스 설정·필터를 유지하도록 설계되어 있습니다. 템플릿 장면 항목의 위치·크기·배치는 저장된 설정으로 다시 적용됩니다. 아래 범위의 격리된 Windows OBS 32.2.2 이관·보존 검수를 통과했습니다. 실제 실패 후 복구는 아직 미검증이며 자동 상태 테스트는 별도 근거입니다.

Windows OBS 32.2.2의 격리된 portable 복사본에서 검수용 프로필·장면 모음을 사용했습니다. 0.9.0 개인 ZIP 적용 → 생성된 config.js와 참조 업로드 PNG만 0.9.1 배포 폴더로 이관 → 새 개인 ZIP 적용을 확인했습니다. 원본 색상 소스 설정·사용자 색상 필터, 다른 장면 항목의 위치, 구형 OST 장면·그룹이 유지되었습니다. ALO4OBS 장면 재사용, Main 원본 소스 재연결, 재적용 시 중복 없음, 미디어의 새 local_file 경로를 확인했고 실제 OBS 화면에 업로드 PNG의 주황 영역이 표시되었습니다. Chrome HTTP에서도 저장·재열기와 10개 설정 그룹 일치를 확인했습니다. 개인 웹 위젯·실제 카메라·실제 캡처·방송·macOS·file:// 설정 편집기·운영체제 파일 선택창·실제 실패 후 복구는 미검증입니다.

ALO4OBS 업데이트를 되돌릴 때는 업데이트 전 장면 모음 백업을 별도 복구용 장면 모음으로 가져옵니다. 현재 장면 모음을 덮어쓰지 마세요. 버전이 맞는 기존 Lua 스크립트와 기존 적용 폴더 전체를 복원하고 원본 소스 연결을 확인합니다. 업데이트는 같은 ALO4OBS 장면을 재사용하고 생성된 브라우저 소스의 local_file을 새 폴더 경로로 바꿉니다. 따라서 같은 장면 선택과 기존 Lua 재등록만으로는 이전 상태로 돌아가지 않습니다. 보존한 기존 장면으로 바로 전환하는 방법은 기존 OST 장면이 별도로 남는 OST 병행 이관에만 해당합니다. 이전 장면 모음과 적용 폴더 전체 백업이 없으면 완전한 복구를 보장할 수 없습니다. 실제 실패 후 복구는 아직 미검증입니다. 실행 중 스크립트의 복구 스냅샷은 같은 스크립트·버전에서만 쓸 수 있습니다. HTTP 미리보기만으로 직접 파일 실행, 운영체제 압축 해제·파일 선택창, macOS 지원을 검증했다고 할 수 없습니다.

예약된 이름과 공유 소스

다른 장면을 직접 편집하지는 않지만 생성된 ALO · 소스·그룹을 다른 장면에서 재사용했다면 갱신된 콘텐츠를 공유합니다. 꺼진 그룹에 있던 원본 소스는 숨겨진 최상위 항목으로 남습니다. 예약 이름 충돌 오류가 나오면 해당 항목을 확인하고 필요하면 백업으로 복구하세요. 무관한 소스를 임의로 삭제하지 마세요.

웹 위젯 주소는 어디서 가져오나요?

채팅·번역·후원 등 원하는 서비스에서 OBS 표시용 위젯 URL을 복사해 원하는 패널의 웹 주소에 입력합니다. 서비스의 설정 화면 주소와 표시용 주소는 다를 수 있습니다. 위젯 내부 글꼴·색·소리·작동은 제공자에서 설정하세요.

개인 위젯 URL에는 토큰이 들어갈 수 있으므로 설정 ZIP을 공개하지 마세요.

OBS 소스와 이미지·영상을 쓰려면?

OBS에 캡처·카메라·미디어 같은 개별 영상 소스를 먼저 만듭니다. 장면과 그룹은 패널 소스로 선택할 수 없습니다. 해당 패널을 OBS 소스로 설정하고 스크립트에서 그 패널 이름의 소스를 선택하세요. 같은 OBS 소스를 두 칸에 중복 선택할 수 없습니다. 파일은 패널의 이미지/영상에서 올리거나 직접 미디어 URL을 입력합니다. 일반 동영상 시청 페이지 주소는 미디어 파일 주소가 아닙니다.

프레임 구조, 모서리, OBS 위치는 어떻게 동작하나요?

왼쪽·오른쪽 프레임과 간격 설정이 일곱 패널의 위치를 정하므로 숫자 좌표를 직접 편집하지 않습니다. OBS에서 직접 옮긴 위치는 다음 자동 배치 때 저장된 배치로 돌아옵니다. 원본 OBS 소스 설정을 보존하도록 설계되었으며 투명 모서리용 알파 마스크는 템플릿 전용 그룹에 적용됩니다. 같은 설정을 재적용해도 템플릿 소스가 중복 생성되지 않습니다.
