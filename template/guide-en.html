Configure and connect OBS

Follow the picture first. Open the headings below when you need the details.

Quick start

Required setup

1. Prepare OBS

Use OBS Studio 30.1 or newer with Browser Source and Tools → Scripts available.

In Settings → Video, use a 1920 × 1080 base canvas. If your production profile uses another size, choose or create a separate profile for this setup; do not arbitrarily change your production profile.

2. Open the distribution

Extract the entire ALO4OBS-v0.9.1.zip distribution, then open its root settings.html (it opens files/settings.html). Do not open pages inside the ZIP.

3. Choose panels and content

Select Main, Sub 1–3 or Side 1–3. In Content type, choose None, OBS source, Web URL, or Image/video. These roles are not fixed to games, chat or cameras.

For OBS source, first create an individual capture or camera source in OBS and check that it works. Scenes and groups are not panel source choices. For Web URL, enter the provider’s OBS display URL; for Image/video, upload a file or enter a direct media URL. A watch-page URL is not a media file.

4. Set layout and style

Main stays enabled. Choose the Sub and Side counts; Sub fills left to right and Side top to bottom. Set Main/Sub row order, Side column position, sizes, spacing, fill and stroke. Check the layout preview. Samples do not connect real accounts; the preview cannot show your original OBS captures.

5. Save and extract your personal ZIP

Click Save as ZIP (Korean: ZIP 파일로 저장). The result is OBS-settings.zip, your personal application package. It is different from the distribution ALO4OBS-v0.9.1.zip.

Extract all of OBS-settings.zip into a new permanent folder. Keep OBS-script.lua, JSON configuration, masks, assets/ and runtime files together. The script reads relative to its own folder; moving only the Lua file breaks those paths. The runtime package is for OBS and does not contain the settings editor.

6. Connect OBS and check the result

In OBS, open Tools → Scripts → + and select OBS-script.lua from that extracted personal folder. If the controls appear in Korean, enable English UI (reload after changing) and reload the script.

For each OBS source panel you want to display, select the matching original source in its Main/Sub/Side script selector. Use distinct sources for different panels. A blank selector can intentionally leave a panel empty. Click Apply saved settings / Auto layout (Korean: 저장한 설정 / 자동 배치 적용).

Open the generated ALO4OBS scene. Check capture, camera, live widgets and media in OBS before switching your broadcast to it. The settings preview confirms layout only. Browser edits do not automatically update OBS: export again, extract the whole package, register the new script path or update the application folder and reload, check selectors, then Apply again.

Extra tips

Layout controls

The seven slots are Main, Sub 1–3 and Side 1–3. None of them is locked to a game, chat, or camera. For each panel, choose None, OBS source, Web URL, or Image/video, then set its style. Panel names help identify slots in the preview and are hidden from OBS output. Samples do not connect real accounts.

By default, Main and Sub 1–3 sit in the left frame; Side 1–3 fill the right frame from top to bottom. Main is always enabled. Use the Number of Sub panels and Number of Side panels sliders to choose 1, 2 or 3 each. Sub panels fill from the left and Side panels from the top. Use the Swap Main and Sub rows switch to reverse their vertical order. Turn on Place Side column on the left to move the entire Side column to the left and the Main/Sub frame to the right. Side 1–3 keep their top-to-bottom order.

Spacing in Global settings sets both the gap between panels and the margin at the screen edges: Extra narrow 8 px, Narrow 16 px, Medium 24 px, Wide 32 px (default) or Extra wide 48 px. The Side frame stays 440 px wide on either side; the Main/Sub frame uses the rest.

Choose Auto or Manual for the height of Side 1–3 and for the width of Sub 1–3. Main and Side panels always use automatic width. Auto fills remaining space. Manual keeps the pixel size entered with the number input or slider. Limits update with the active panels, spacing and other manual sizes. When every enabled Sub is Manual and their widths do not match the frame, nothing is resized: a warning about empty space or overflow appears next to the Sub width setting. Saving and applying in OBS still work; on an overflow the Sub widths shrink to fit on screen.

Uploaded images and videos may be restored when you reopen the same settings page in the same browser. Save a settings ZIP before clearing browser data or moving files.

Sub panels have a minimum width based on their 16:9 reference row height (206 px by default). Other minimums remain 50% and maximums 150% of the automatic size, subject to frame boundaries and peer space. Sub panels use automatic height. Main offers Auto, 16:9 (default), 21:9, and 32:9. Auto fills the height remaining above or below the Sub row. Drag near a 1:1 or 16:9 mark to snap to that ratio; marks are recalculated from the other dimension. Numbers and keyboard controls remain precise.

OBS versions and verification scope

The script uses obs_sceneitem_get_info2 / obs_sceneitem_set_info2, introduced in 30.1. This is the API minimum; Isolated Windows OBS 32.2.2 migration checks passed in the scope below. macOS is unverified for this version.

Update an ALO4OBS installation

Export your OBS scene collection, back up the entire old application folder, and record every script source selection before updating. Keep old packages intact; extract the new distribution into a separate folder.

The editor reads config.js, not JSON imports. After a successful old-script Apply, copy its generated config.js into the new distribution’s files/ folder. Copy only personal media referenced by its assets/... paths, preserving those paths. Keep the new config.public.js, internal scripts and fonts. If config.js is missing, return to the old version and Apply once to generate it, or manually reconfigure while keeping the old environment. Renaming JSON is not an import. A browser draft at a new path is not guaranteed.

Open the new root settings.html, check values and media, export a new OBS-settings.zip, and extract it into a new permanent folder. After recording mappings, remove only the old Lua registration (this does not delete scenes). Add the new Lua path and reselect the original sources before Apply; a new registration does not inherit old selector values from JSON.

Move from legacy OST

Keep the old OBS Streaming Template scene, OST · groups, originals and complete script folder. Export the scene collection and record source selections. Stop/remove only the old script registration, retaining its Lua file and backup. Configure the new version with the same originals, add its script, reselect sources and apply.

The new ALO4OBS scene is created separately. Verify before switching; keep the old scene for rollback. There is no automatic OST scene migration. Do not blanket-delete sources or groups.

Rollback and verification limits

Apply is designed to reuse the ALO4OBS scene and ALO · items, preserve original source settings/filters, and intentionally restore template scene-item transforms and layout. The isolated Windows OBS 32.2.2 migration/preservation checks below passed. Recovery after a real failure remains unverified; automated state tests are separate evidence.

Windows OBS 32.2.2 was checked in an isolated portable copy with a QA profile and scene collection: a 0.9.0 personal ZIP was applied, its generated config.js and referenced uploaded PNG were transferred into the 0.9.1 distribution, and a new personal ZIP was applied. The checks confirmed original color-source settings and a user color filter, another scene’s item position, legacy OST scene/groups, ALO4OBS scene reuse, Main source reconnection, no duplicate items on reapply, and the media source’s new local_file path. The uploaded PNG rendered as an orange region in the actual OBS view. Chrome HTTP checks also confirmed save/reopen and all ten settings groups. These checks do not verify personal web widgets, physical cameras, real captures, broadcasting, macOS, the file:// settings editor, OS file pickers, or recovery after a real failure.

For an ALO4OBS update rollback, import the pre-update scene-collection backup into a separate recovery collection; do not overwrite the current collection. Restore the matching old Lua script and complete old application folder, then check the original source mappings. The update reuses the ALO4OBS scene and changes generated browser-source local_file paths to the new folder. Selecting that same scene and registering old Lua alone does not restore the previous setup. Returning directly to the preserved old scene applies only to parallel legacy OST migration, where that scene remains separate. Full recovery cannot be guaranteed without the previous scene-collection and complete application-folder backups. Recovery after a real failure remains unverified. A live rollback snapshot works only with that same running script/version. HTTP preview does not establish direct-file browser compatibility, native extraction/picker behavior or macOS support.

Reserved names and shared sources

Other scenes are not edited directly, but reusing generated ALO · sources/groups in another scene shares their updated content. Original sources from disabled groups are retained as hidden root items. If Apply reports a reserved-name collision, inspect the reported item and restore your backup if needed; do not delete unrelated sources blindly.

Where do I get a web widget URL?

Copy the OBS display URL from any chat, translation, alert, donation, or other widget provider. Paste it into Web URL on the panel you choose. A provider's settings-page URL may differ from its display URL. Configure the widget's own fonts, colors, audio, and running state with its provider.

A private token may be embedded in a widget URL; keep your settings ZIP private.

How do I use an OBS source or image/video?

First create an individual video source in OBS, such as a capture, camera, or media source. Scenes and groups cannot be selected as panel sources. Set your chosen panel to OBS source, then choose it in that panel's matching panel-name script selector. One OBS source cannot be selected twice. For a file, choose Image/video and upload it or enter a direct media URL. An ordinary video watch-page URL is not a media-file URL.

How does the frame structure, corners and OBS positioning work?

The left and right frames and the spacing setting place the seven panels without manual pixel coordinates. Moving a template item in OBS is temporary: the next Apply restores the saved layout. The script is designed to retain original OBS source settings; alpha masks are applied to template-managed groups. Applying the same settings again does not duplicate template sources.

The preview is blank or OBS shows old settings
  • A browser may block some local file access in the preview. You can still enter settings and save the ZIP; verify in OBS.
  • Export a new settings ZIP, extract the whole package, register the new path or update the application folder and reload the script, check source selections, then apply automatic layout again. Refresh the OBS browser-source cache if needed.
  • For web widgets, check that you used the OBS display URL. A stopped program or offline channel may show nothing.
Can I share my settings links?

Widget URLs may contain private tokens. Do not post settings files or ZIPs in public repositories or chats.
